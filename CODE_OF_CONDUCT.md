# Code of Conduct

## Our standard

This repository aims to keep technical discussion focused, respectful and reproducible.

Examples of constructive participation include:

- reporting bugs with enough evidence to reproduce them;
- challenging technical claims with measurements, code or references;
- documenting negative results and limitations;
- reviewing contributions without attacking the contributor;
- keeping security research within clearly authorized and defensive scope.

Unacceptable behavior includes harassment, discrimination, deliberate disruption, doxxing, credential sharing, or requests to use the project for unauthorized access or harm.

## Security-research boundary

For repositories that contain security tooling or experiments, contributions should remain within benign, defensive, educational, or explicitly authorized research use. Requests that materially expand harmful capability may be declined even if technically interesting.

## Enforcement

Project maintainers may edit, hide or remove content that violates these expectations and may restrict participation when necessary.

For security-sensitive reports, use the process documented in `SECURITY.md` rather than posting exploit details in a public issue.
